How to Upload Files & Run Analysis

Getting Started with File Upload

DeCoder allows you to upload your code files directly for instant analysis. Follow these steps:

Supported File Types:

Python (.py), JavaScript (.js, .jsx, .ts, .tsx), HTML (.html, .htm), CSS (.css), C/C++ (.c, .cpp, .h), C# (.cs), Go (.go), Java (.java), PHP (.php), Ruby (.rb), Swift (.swift), Kotlin (.kt), Rust (.rs)

  1. Navigate to Upload Page

    Click on "Upload Code" in the navigation bar at the top of the page.

  2. Enter Analysis Details
    • Analysis Name: Give your analysis a descriptive name (required)
    • Description: Optional description to help you remember the project
  3. Select Files

    Click "Choose Files" and select your code files. You can select multiple files at once (up to 100 files).

  4. Upload & Analyze

    Click the "Upload and Analyze" button. The system will process your files and start the analysis automatically.

  5. View Progress

    You'll be redirected to the analysis page where you can watch the progress in real-time. The analysis typically takes 30-60 seconds.

File Size Limits:
  • Maximum file size: 16MB per file
  • Maximum total upload: 160MB
  • Maximum number of files: 100
Tips for Best Results
  • Upload all related files from your project for comprehensive analysis
  • Ensure files are UTF-8 encoded text files
  • Use descriptive names for your analyses to easily find them later
  • Include configuration files and documentation for better insights

How to Connect GitHub & Run Analysis

Importing Code from GitHub

DeCoder can directly analyze code from GitHub repositories without downloading files manually.

Note: Currently supports public GitHub repositories. Private repository support requires authentication.
  1. Navigate to GitHub Import

    From the dashboard, click the "Import from GitHub" button or navigate using the menu.

  2. Enter Repository URL

    Paste the full GitHub repository URL, for example:

    https://github.com/username/repository
  3. Provide Analysis Details
    • Analysis Name: Enter a name for this analysis
    • Description: Optional description
  4. Import & Analyze

    Click "Import and Analyze". DeCoder will clone the repository and start the analysis process.

  5. Monitor Progress

    Track the import and analysis progress on the results page. Large repositories may take a few minutes.

GitHub Repository Requirements
  • Repository must be public (or you must have access)
  • Repository should contain code files in supported languages
  • URL must be a valid GitHub repository URL
Pro Tip: GitHub import is ideal for analyzing open-source projects, reviewing code before contributing, or getting insights into unfamiliar codebases.

Understanding the View Results Page

Analysis Results Overview

The View Results page provides comprehensive insights into your code. Here's what each section means:

Project Health Score

A visual indicator at the top showing overall code quality:

  • Excellent (95%): Simple, well-structured code with low complexity
  • Good (75%): Moderate complexity, generally maintainable
  • Complex (50%): High complexity, may need refactoring

The score is calculated based on the number of files, functions, and classes in your project.

Executive Dashboard

High-level project statistics including:

  • Total Files: Number of files analyzed
  • Languages: Programming languages detected
  • Source Type: Upload or GitHub import
  • Language Badges: Visual indicators of technologies used
Static Analysis Section

Detailed code metrics and patterns:

  • Functions & Classes: Count of defined functions and classes
  • Imports: External dependencies and libraries used
  • Code Patterns: Common programming patterns detected
  • File Details: Individual file breakdowns with line counts
AI Insights Section

AI-generated analysis providing:

  • Architecture Overview: How your code is structured
  • Code Quality Assessment: Strengths and weaknesses
  • Security Findings: Potential security concerns
  • Improvement Recommendations: Suggested enhancements
View Full Documentation: Click the "View Documentation" button to see a detailed, structured report of all findings in an easy-to-navigate format.

Trust Centre

In memory analysis — no storage of code.

Your code is processed entirely in memory and is never written to disk or retained after analysis.

Data Privacy & In-Memory Processing

DeCoder is built with privacy at its core. When you upload code or import from GitHub:

  • All analysis is performed entirely in memory — your code is never stored on our servers
  • Uploaded files are processed in real time and discarded immediately after analysis completes
  • No copies of your source code are retained, cached, or backed up
  • Analysis results (mind maps, documentation, metrics) are stored for your convenience but contain no raw source code
Security Practices

We follow industry best practices to keep your data safe:

  • Encrypted connections: All data transmitted between your browser and DeCoder is encrypted using TLS/HTTPS
  • Access controls: Your analyses are private to your account and cannot be accessed by other users
  • No third-party sharing: Your code and analysis results are never shared with third parties
  • Secure authentication: User accounts are protected with securely hashed passwords
AI & Data Usage

DeCoder uses AI to generate insights about your code. Here is how we handle that responsibly:

  • AI is used solely for analysis — generating documentation, mind maps, quality metrics, and recommendations
  • Your code is not used to train any AI or machine learning models
  • Analysis results and generated documentation belong entirely to you
  • AI processing happens on demand and code is not retained after the AI has produced its output
Your Controls

You are always in control of your data within DeCoder:

  • Delete analyses: Remove any analysis and its generated results at any time from your dashboard
  • Manage your account: Update your profile or delete your account through account settings
  • Onboarding preferences: Choose whether to see the welcome guide on login
  • No lock-in: Your generated documentation and insights can be viewed and used as you see fit
Contact & Questions

If you have any questions, concerns, or requests related to trust, privacy, or security:

  • Reach out via the contact options provided in your account settings
  • We are committed to transparency and will respond to all trust-related enquiries promptly
Our Commitment: DeCoder is designed to help you understand your code better, without compromising your privacy or intellectual property. Your trust is fundamental to everything we do.

Interactive Mind Map

Visualising Your Codebase

The Mind Map is an interactive visual graph that maps out the structure of your entire project at a glance. It is available on the Analysis Results page under the Mind Map tab.

What the Mind Map Shows
  • Files — each source file in your project appears as a node
  • Classes & Functions — key code structures within each file
  • Dependencies — connections between modules that import from one another
  • Language groupings — nodes are colour-coded by programming language
How to Interact
  • Zoom in/out — use your mouse scroll wheel or the zoom buttons to focus on specific areas
  • Pan — click and drag the background to move around the graph
  • Click a node — select a file or component node to highlight its connections
  • Reset view — use the reset button to return to the default full-project view
Pro Tip: The Mind Map is especially useful for understanding unfamiliar codebases. Start at the central node and follow the connections outward to trace the application's flow.

Code Explorer

Browsing Your Source Files

The Code Explorer tab on the Analysis Results page lets you browse and read every file that was included in your analysis, without leaving DeCoder.

Navigating Files
  • A file tree on the left lists all analysed files organised by folder structure
  • Click any file name to load its content in the viewer panel on the right
  • Files are syntax-highlighted according to their language for easy reading
File Metadata

Above each file's content you will see key metadata including:

  • File name and path within the project
  • Programming language detected
  • Total line count
Note: The Code Explorer displays the files exactly as they were at the time of analysis. It is a read-only view — no changes can be made to your code from within DeCoder.

AI-Enhanced Code Understanding

Plain-English Explanations of Your Code

The AI-Enhanced Code Understanding tab uses OpenAI's GPT models to go beyond raw metrics — it reads your code and explains it in plain English, file by file.

Per-File AI Summaries

For each file in your project, the AI generates:

  • Module purpose — a concise description of what the file does and its role in the project
  • Function explanations — what each function or method does and what it returns
  • Class descriptions — the responsibility of each class and how it relates to others
  • Key logic highlights — important algorithms or patterns worth noting
Project-Wide Insights
  • Architecture overview — how the files and modules fit together as a whole system
  • Technology stack identification — frameworks, libraries, and tools detected in use
  • Entry points — where the application starts and how requests flow through it
Processing Time: AI understanding is generated during the analysis phase. Larger projects with many files may take longer. The results are cached so you can revisit them instantly at any time.

Code Smells Analysis

Identifying Problem Areas in Your Code

The Code Smells Analysis tab automatically detects common coding anti-patterns and quality issues that make code harder to maintain, test, or extend.

Types of Code Smells Detected
  • Duplicated code — repeated logic that should be extracted into a shared function
  • Long methods — functions that are too large and do too many things at once
  • Tight coupling — components that are too dependent on each other, making changes difficult
  • Hardcoded credentials — passwords, API keys, or secrets embedded directly in code (a security risk)
  • Magic numbers — unexplained numeric constants that should be named variables
  • Unsafe functions — use of dangerous calls such as eval()
  • SQL injection risks — patterns that may allow malicious database queries
Severity Levels

Each detected issue is assigned a severity level:

  • Critical — security risks requiring immediate attention
  • High — significant quality issues affecting maintainability
  • Medium — moderate issues worth addressing in your next refactor
  • Low — minor style or convention issues
Next Step: Use the Remediation Plan (accessible from the analysis page) to turn the detected code smells into a structured action plan with time and cost estimates.

Remediation Plan

Turning Findings Into an Action Plan

The Remediation Plan converts the code smells and issues detected in your analysis into a structured, prioritised work plan with realistic time and cost estimates.

How to Access the Remediation Plan
  1. Open any completed analysis from your Dashboard
  2. Click the "Remediation Plan" button on the analysis results page
What the Plan Contains
  • Prioritised issue list — items ordered from Critical to Low severity
  • Estimated hours per issue — how long each fix is expected to take
  • Role assignments — which type of developer (junior, senior, architect) is best suited to each task
  • Total cost estimate — calculated from your configured hourly rates
  • Timeline projection — how many weeks the full remediation will take
Customising the Plan Settings

Expand the Plan Settings panel to tailor the estimates to your organisation:

  • Hourly rates — set your own rates for each developer role
  • Hours per week — how many productive hours your team works per week
  • Parallel workstreams — how many developers can work on remediation simultaneously
  • Currency — display costs in your preferred currency

Changing any setting instantly recalculates the entire plan.

Clean Code: If no code smells are detected in your project, the Remediation Plan will confirm your codebase is clean and no action is required.

Exporting Your Analysis

Downloading a Full Summary Report

Once an analysis is complete, you can export a comprehensive summary as a Microsoft Word document (.docx) to share with your team, include in reports, or archive for future reference.

How to Export
  1. Open a completed analysis from your Dashboard
  2. Click "Export Summary" — the blue button in the top-right area of the analysis page
  3. Your browser will download a .docx file automatically
What the Export Includes
  • Project overview and key statistics
  • Technology stack and detected languages
  • Architecture summary
  • Quality metrics and health score
  • Security findings
  • AI-generated recommendations
  • File-by-file breakdown
Availability: The Export Summary button only appears for analyses that have successfully completed. In-progress or failed analyses cannot be exported.

Sharing & Team Collaboration

Sharing Analyses With Your Team

On Team and Enterprise plans, you can share individual analyses with everyone in your workspace so colleagues can view the results without needing to run the analysis themselves.

Private vs Shared Toggle

Each analysis you own has a visibility toggle on its results page:

  • Private — only you can see this analysis (the default for all new analyses)
  • Shared — all members of your workspace can view this analysis from their Dashboard

Click the toggle button to switch between Private and Shared at any time.

What Team Members Can See

When an analysis is shared, team members can:

  • View all results tabs — Overview, Mind Map, Code Explorer, AI Understanding, Code Smells
  • Access the Documentation page
  • Open the Remediation Plan
  • Export the summary report

Team members cannot delete or modify an analysis that belongs to another user.

Plan Requirement: Sharing is available on Team and Enterprise plans only. Solo plan users can upgrade via Team Admin or by contacting sales.

Team Admin

Managing Your Workspace & Team Members

The Team Admin page is available to workspace administrators and lets you manage your organisation's DeCoder workspace, members, and access levels.

How to Access Team Admin

Click "Team Admin" in the navigation menu. This option is visible to users with an admin role in their workspace.

Workspace Settings
  • Workspace name — rename your organisation's workspace at any time
  • Subscription tier badge — see your current plan (Solo, Team, or Enterprise) at a glance
  • Seat usage bar — a visual indicator showing how many of your available seats are in use
Inviting Team Members
  1. Enter the email address of the person you want to invite in the Invite section
  2. Select a role — Admin (can manage the workspace) or Reviewer (view-only access to shared analyses)
  3. Send the invitation — the invitee receives an email with a link to register and join your workspace
Roles Explained
  • Admin — full access: can run analyses, share results, invite/remove members, and manage workspace settings
  • Reviewer — read-only access to analyses that have been shared with the team; cannot run new analyses or manage members
Removing Members

Admins can remove a team member from the workspace at any time from the members list on the Team Admin page. Removed members immediately lose access to all shared analyses.

Seat Limits: Team plan workspaces support up to 5 members. Enterprise plan workspaces have unlimited seats. If you reach your seat limit, contact sales to upgrade.
