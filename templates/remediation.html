About These Estimates

These estimates are generated based on industry-standard benchmarks for code remediation effort, adjusted for the severity and complexity of each identified issue. Actual timelines may vary depending on team familiarity with the codebase, testing requirements, and deployment constraints. Resource rates can be customised using the Plan Settings panel above to reflect your organisation's specific costs. The timeline supports parallel workstreams which can be configured to reduce the overall duration. Additional overhead for QA testing, project management, and product ownership is included automatically.

How Estimates Are Calculated
1. How Issues Are Categorised

Each code smell detected during analysis is automatically matched to one of 12 predefined categories based on keywords in its description. If no specific match is found, it falls into the General Code Quality category.

6. Risk Classification

Every category is classified into one of three risk types to help prioritise work:

Security & Compliance

Issues that could lead to data breaches, regulatory penalties, or compliance failures. These are prioritised first.

Operational Risk

Issues that impact system stability, user experience, or production reliability. These are addressed second.

Technical Debt

Issues that increase long-term maintenance costs and slow development velocity. These are planned for ongoing improvement.

7. Timeline & Gantt Chart

The timeline is calculated as follows:

  • A working week is assumed to be {{ calc_info.hours_per_week }} hours of productive development time.
  • Total hours for each category are divided by {{ calc_info.hours_per_week }}, then rounded up with a small buffer to avoid underestimation. The minimum is always 1 week.
  • Categories are scheduled with higher-risk categories first (Security & Compliance, then Operational Risk, then Technical Debt).
  • Within each risk group, categories are ordered by the number of High-severity issues (most first), then by total estimated hours (highest first).
  • The plan supports parallel workstreams (1–4), distributing tasks across multiple streams to reduce the overall timeline.
Note: Use the Plan Settings panel to configure parallel workstreams. With multiple streams, tasks are distributed to the earliest available stream, reducing total project duration.
8. Total Cost Formula

The total cost is the sum across all issues:

Total Cost = ∑ (Base Hours × Severity Multiplier × Hourly Rate)

For each issue, across all categories

9. Contingency Buffer

An optional contingency buffer can be applied to account for unknowns, estimation inaccuracies, and unforeseen complexity. Real-world projects typically include 15-25% contingency.

  • Configurable from 0% to 50% via the Plan Settings panel (default: 0%).
  • Applied as a percentage of the base total hours and cost after all resource allocations (developers, QA, PM, PO) are calculated.
  • Displayed separately in the Resource Requirements table so stakeholders can see the base estimate vs. the buffer.
Example: A base estimate of 100h at {{ calc_info.currency_symbol }}10,000 with a 20% contingency buffer = 120h and {{ calc_info.currency_symbol }}12,000 total.
